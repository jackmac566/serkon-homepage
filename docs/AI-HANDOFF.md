# AI / 开发者接手说明

这份文件用于防止后续维护者在不了解历史约束时“重做一遍”或误伤线上数据。

## 不可破坏的生产约束

- 国内固定网址：`https://serkon-homepage-cn.pages.dev/`
- 复用现有 Cloudflare Pages 项目，不新建同名替代项目。
- 复用现有 D1 数据库，不删除、不清空、不重置表。
- 保留公共大厅、共享影像、排行榜、在线状态和站长管理能力。
- 管理 secret 只存在于部署环境，不进入 Git。
- 每次正式更新都在 `data/releases.json` 追加版本，不改写历史版本。

## 变更顺序

1. 先说明问题、依据和风险。
2. 只改与需求相关的源码。
3. 运行测试和构建检查。
4. 检查桌面、手机竖屏、手机横屏、键盘与减少动画场景。
5. 检查中文和英文界面。
6. 检查 API 权限、输入边界和错误状态。
7. 生成增量部署产物；不得携带数据库导出或 secret。
8. 部署后验证固定网址、版本地址和现有数据接口。

## 数据结构

- `life_photos` / `life_photo_blobs`：共享影像元数据与图片内容
- `lobby_messages`：公共大厅留言
- `lobby_reports` / `lobby_moderation_log`：大厅举报与管理记录
- `lobby_presence`：短时在线状态
- `inspiration_scores` / `inspiration_challenges`：游戏排行榜与对局
- `community_votes` / `planet_contributions`：互动档案数据

迁移必须增量执行。禁止用“为了方便”重建生产数据库。

## 共享影像审核现状

现有系统会检查：

- 登录身份和同源请求
- 文件大小、声明格式与真实文件头
- 上传频率和个人总量
- 上传者或管理员的删除权限

现有系统不会自动判断：

- 上传者是否真正拥有版权
- 肖像授权是否有效
- 图片语义是否违规
- 图片是否来自其他平台或权利人

因此当前采用“上传者负责 + 站长事后人工处理”。若访问量增长，优先增加免费的照片举报入口、管理员审核队列和处置日志；不要用不确定收费的第三方审核服务破坏 0 成本原则。

## 开源边界

MIT 只覆盖可分离代码。个人照片、音乐、身份资料、作品和品牌素材不随代码授权。不得把 GitHub 开源误写成所有内容可自由商用。
